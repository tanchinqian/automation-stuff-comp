# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary users are dispensing-line operators and process engineers in electronics / semiconductor manufacturing.

- New or less-experienced technicians and operators need guided troubleshooting when a dispensing defect appears (what went wrong, what to check first).
- Experienced process engineers want faster preliminary diagnosis and structured, evidence-backed analysis plus a shareable report before deeper investigation.

## Product Purpose

PasteTrace helps manufacturers identify and diagnose fluid-dispensing problems faster. The user describes or uploads a dispensing problem, the assistant asks targeted questions, identifies the likely defect, ranks possible causes with confidence and reasoning, recommends a logical troubleshooting sequence, and generates a report. It is a preliminary troubleshooting aid, not a replacement for engineers.

Success means an operator reaches a confident, correct first troubleshooting step in less time than an unassisted or experience-dependent workflow.

## Positioning

A combined, transparent engine: a domain-grounded dispensing failure-mode knowledge base drives explainable rule-and-evidence scoring, paired with AI vision (a trained YOLOv8s detector with a classical per-pad CV fallback) and a case-based learning database. Every ranking is traceable to the symptom evidence and prior cases that produced it, and the core path runs on-device with a local pipeline server adding the trained vision pipeline and the Gemini-backed chat when present. A generic chatbot or a cloud API wrapper cannot truthfully claim this transparent, learning pipeline.

## Operating Context

- Used on a shop floor or demo station in a browser. Core analysis, learning and reporting work with no server or API key; the optional local server adds the trained vision pipeline and the Gemini-backed chat.
- Workflows: describe the problem in free text via the assistant chat (parsed by the layered NLU); optionally inspect a dispensing image through the server pipeline or the on-device vision fallback; review the ranked causes and reasoning; follow the recommended action plan; feed back which cause actually fixed the issue.
- Learning database persists locally (IndexedDB) and updates cause priors from resolved cases.
- A troubleshooting report can be generated as an on-device PDF (problem, defect, analysis, causes, confidence, actions, engineer notes).

## Capabilities and Constraints

- Capabilities: free-text problem intake in the assistant chat; defect identification with confidence; ranked causes with likelihood bars and explained reasoning; troubleshooting action plan; AI vision (server pipeline: YOLOv8s leg detector + MobileNetV2 classifier, with on-device ONNX and classical per-pad CV fallbacks); dispensing quality score (shape/size/position/defect-risk to /100); IndexedDB case store merged with the server case log, feeding cause priors; on-device PDF report.
- NLU is a layered fallback: Chrome Gemini Nano, then an on-device model (transformers.js), then an embedded keyword engine. It always works offline; the model download needs internet once.
- Constraints: vanilla TypeScript + Vite, no framework. The browser app talks to an optional local FastAPI pipeline server (server/); without it, vision falls back on-device and the chat falls back to offline templates.
- Undecided: none material.

- No fabricated customer testimonials, benchmarks, or press exist; future work must not fabricate them.

## Product Principles

1. The engine is transparent: every ranking must be explainable from the symptom evidence and prior cases that produced it.
2. Self-contained by default: core analysis, learning, and reporting need no server or API key, and the pipeline degrades gracefully when the local server is unavailable.
3. Domain grounding over generic chat: the knowledge base and CV pipeline encode real dispensing failure modes.
4. Assist, do not replace: the assistant shortens preliminary troubleshooting, never overrides the engineer's judgment.
5. The system learns: resolved cases update priors so it improves with each use.

## Accessibility & Inclusion

The UI targets WCAG AA contrast and keyboard operability on a desktop browser (focus-visible rings, ARIA tab/panel semantics, aria-live for async updates, reduced-motion support). No additional product-specific accessibility requirement was established.
